# polymarket-smoke — контекст проекта

## Что это

Бот для Polymarket-маркетов "Up or Down" (BTC/SOL/ETH/... по 5m/15m/1h),
реализующий стратегию реинвест-прогрессии "N шагов подряд без единого сбоя"
(challenge на N побед подряд, при проигрыше — сброс на базовый стейк).
Цель — набрать почти-гарантированный исход (¢99+) по одному из двух
бинарных outcome (YES/NO), реинвестируя выигрыш в следующий шаг.

Стек: TypeScript / NestJS, TypeORM + PostgreSQL, WebSocket (Polymarket CLOB
market-стрим + внешний ценовой фид), React-дашборд без сборки
(`index.html`, babel standalone в браузере).

Изначально был написан для одного актива/таймфрейма с общим счётчиком
шагов; в ходе этой серии сессий переведён на архитектуру с несколькими
независимыми потоками (актив × таймфрейм), каждый со своей прогрессией.

## Архитектура (ключевые файлы)

- `src/trading/trading.service.ts` — ядро: обнаружение маркетов, два правила
  входа (маркет-тейк / лимитка-фолбэк), запись логов, резолвер, реинвест-
  прогрессия. Самый большой и самый важный файл.
- `src/trading/stream-config.ts` — `STREAMS_CONFIG` (JSON из .env): список
  независимых потоков (`streamKey`, таймфрейм, формат слага, базовый стейк).
- `src/polymarket/gamma-market.service.ts` — читает Gamma API Polymarket
  (публичный, без ключа): текущий/следующий маркет по слагу, исход после
  резолва. Параметризован по `StreamDefinition` — умеет строить слаги двух
  разных форматов (unix-based для 5m/15m, календарный ET-based для 1h).
- `src/polymarket/price-feed.service.ts` — внешний ценовой фид для
  диагностики/ATR-гейта (НЕ тот же путь, которым сам Polymarket резолвит
  маркет через свой CLOB, но с недавних изменений — тот же ИСТОЧНИК цены,
  см. ниже). Мульти-провайдерный, с авто-фолбэком и ATR, масштабируемым под
  таймфрейм каждого потока.
- `src/polymarket/clob-public.service.ts` — публичный CLOB API (лучшая
  котировка, полный стакан, тик-сайз, минимальный размер ордера).
- `src/polymarket/market-ws-stream.ts` — WS-подписка на живой стакан
  конкретного маркета (book/price_change/tick_size_change).
- `src/polymarket/book-fill.util.ts` — честный проход по уровням стакана
  (VWAP), а не "весь объём по лучшей цене".
- `src/polymarket/polymarket-trader.service.ts` — боевой торговый клиент
  (`@polymarket/clob-client`), используется только при `SMOKE_START=false`.
- `src/entities/attempt.entity.ts`, `market-log.entity.ts` — состояние
  попытки (шаг, стейк) и лог каждого шага (диагностика, исход, профит).
- `src/analytics/analytics.controller.ts` — `/analytics/summary`,
  `/analytics/losses`: бэнкролл, разбивка по потокам, лучшие попытки.
- `index.html` — дашборд: табы по бэкендам (разные деплои под разные
  активы) + табы по потокам (таймфреймы внутри одного бэкенда).
- `scripts/verify-trading-logic.ts` — ad-hoc юнит-тесты на фейках (без БД и
  сети), гоняется через `npx tsx`. **Держать в актуальном состоянии** —
  единственная защита от регрессий при следующих правках.
- `scripts/measure-book-depth.ts` — отдельный долгоживущий процесс, копит
  JSONL со реальной ask-глубиной на ¢99+ по каждому потоку (для проверки,
  реалистична ли цель "N шагов подряд" с точки зрения ликвидности).
- `BACKLOG.md` — план на будущее (пункты 5-7 ещё не реализованы: генерализация
  GammaMarketService под 4ч/1д, приоритизация таймфреймов, Above-маркеты как
  отдельный трек, политика капитала по потокам).

## Что уже сделано (хронологически, по сессиям)

### Сессия 1 — независимые потоки + реинвест-прогрессия (BACKLOG п.1-4)
- Раньше был ОДИН общий счётчик шагов на все активы сразу и константная
  ставка (`BET_AMOUNT`). Теперь `STREAMS_CONFIG` — независимые потоки
  (`streamKey` = актив×таймфрейм), у каждого свой `Attempt`, свой прогресс.
- **Реинвест-прогрессия**: `Attempt.currentStake` не константа. Старт
  попытки = `baseStake` потока; после каждого выигрыша
  `currentStake = filledAmount/entryPrice` — по ФАКТИЧЕСКОЙ цене исполнения
  этого шага (VWAP гуляет по тирам лимитки/маркет-тейка), не по константе
  ¢99. При проигрыше — новая попытка, сброс на `baseStake`.
- Слаги маркетов проверены вручную на живых данных: 5m/15m —
  `{prefix}-{unix_start}`; 1h — календарная ET-строка
  (`bitcoin-up-or-down-september-9-2026-7pm-et`), НЕ unix-таймстамп.
  `GammaMarketService` умеет оба формата через `kind: 'interval'|'hourly-et'`.
- `scripts/measure-book-depth.ts` добавлен для замера реальной глубины
  стакана перед тем, как доверять цели "500 шагов" как достижимой.
- Фронтенд: карточки прогресса и таблица попыток теперь показывают
  `streamKey` и текущий стейк, а не общий счётчик.

### Сессия 2 — фикс WS Binance (гео-блок) + мульти-провайдерный фид
- Реальный инцидент: Binance WS отвечал `451 Unavailable For Legal Reasons`
  на handshake (гео-блокировка по IP хостинга) — фид был мёртв ВСЮ сессию,
  а не эпизодически, вся диагностика (`referencePrice`/`priceAtEntry`)
  отсутствовала на 100% входов.
- Исправлено: `PriceFeedService` теперь мульти-провайдерный
  (`FEED_PROVIDERS`), с авто-переключением после N подряд неудачных
  подключений (`FEED_PROVIDER_FAIL_THRESHOLD`). Плюс опциональный прокси
  (`FEED_PROXY_URL`, http/https/socks5) на случай, если геоблок задевает
  все провайдеры сразу.

### Сессия 3 — окно входа + ATR-гейт fail-closed (по реальным сливам)
- Разобраны два реальных слива на eth-updown-5m: оба случились на РАННИХ
  входах (ask по ¢99 появлялся за 2-3 минуты до закрытия, рынок ещё не
  "определился", цена успевала развернуться).
- Добавлено: `LAST_ENTRY_WINDOW_SEC` (по умолчанию 60) — ни Правило A, ни
  Правило B вообще не пытаются войти раньше последней минуты до закрытия.
  Тиры лимиток (`LIMIT_TIER2/3_SECONDS`) пересчитаны так, чтобы попадать
  внутрь этого окна (40с/15с вместо 150с/60с).
- `ENTRY_FILTER_ENABLED` теперь `true` по умолчанию (раньше был SHADOW-режим
  "считаем, но не блокируем"). Изменена логика при отсутствии диагностики:
  раньше fail-open (пропускали проверку, входили вслепую), теперь
  **fail-closed** — если фид не отдал ни одного тика к моменту входа, шаг
  ПРОПУСКАЕТСЯ целиком. Философия: упустить сделку лучше, чем потерять
  капитал вслепую.

### Сессия 4 — фронтенд: табы по потокам
- Добавлены клиентские (без доп. запросов) табы по `streamKey` (5m/15m/1h)
  внутри уже выбранного бэкенда/актива — независимо от старых табов
  BTC/SOL/ETH (которые остаются табами по РАЗНЫМ бэкенд-деплоям).
- При выборе конкретного потока показывается его собственная сводка
  (wins/losses/profit), при этом общий бэнкролл остаётся глобальным
  (намеренно — один кошелёк на все потоки сразу).

### Сессия 5 — самый важный разбор: источник цены и масштаб ATR (по логам реальных сливов BTC/SOL)
- **Найден и заменён источник эталонной цены.** Раньше референс/ATR
  считались по Binance/Bybit — приближение, НЕ то, чем Polymarket реально
  резолвит крипто Up/Down маркеты (Chainlink, data.chain.link). Это и
  объясняло расхождения (напр. Bybit-свеча open/close заметно отличались от
  официального "Price to Beat" на самом Polymarket).
  Найден официальный бесплатный источник — Polymarket сам транслирует
  Chainlink-цену через публичный WS `wss://ws-live-data.polymarket.com`
  (топик `crypto_prices_chainlink`, без API-ключа, задокументировано на
  docs.polymarket.com). Теперь это провайдер **по умолчанию**
  (`FEED_PROVIDERS=chainlink,binance,bybit`), Binance/Bybit — фолбэк.
  В каждый `market_logs` пишется `priceSource` — видно, откуда именно
  диагностика в конкретной сделке.
- **Найден реальный баг в расчёте ATR.** Раньше ATR считался по свечам в
  1 секунду × 20 штук = 20-секундное окно, ОДИНАКОВОЕ для 5-минутного и
  часового маркета. На практике это давало обманчиво ОГРОМНЫЙ
  `atrRatioAtEntry` (45-60x) при почти равновероятных входах — потому что
  типичный шум за 20 секунд на порядки меньше типичного дрейфа цены за
  15-60 минут. Гейт в таком виде НЕ отфильтровал бы разобранные плохие
  входы, даже будучи включённым.
  Исправлено: размер свечи ATR теперь считается автоматически НА КАЖДЫЙ
  ПОТОК как `intervalSec*1000 / FEED_ATR_CANDLES` (5m → 15с свечи, 15m →
  45с, 1h → 3мин) — ATR отражает волатильность в масштабе, сопоставимом с
  длительностью самого окна потока. Проверено тестом: несколько потоков,
  шарящих один тикер (напр. все BTC-потоки), теперь ведут независимые
  свечные серии с разным размером свечи.
- Добавлена проверка "протухшего" тика (`FEED_STALE_MS`, по умолчанию 5с) —
  если последний тик по фиду старше порога, диагностика считается
  недоступной (не берётся "какая есть"), что при включённом гейте уходит в
  fail-closed так же, как полное отсутствие тиков.
- Добавлены колонки `orderSentAt`/`orderFilledAt` в `market_logs` — момент
  отправки/выставления ордера и момент фактического исполнения, отдельно от
  цены на входе (нужно для разбора инцидентов "цена успела уйти между
  решением и фактом").
- Прояснено (без изменения кода): реинвест-прогрессия считает от
  `filledAmount/entryPrice`, не от теоретической "чистой" ставки — если по
  пути были частичные исполнения (`fillRatio < 1`), рост будет медленнее
  идеальной геометрии. Это не баг, а следствие честного реинвеста только
  реально вложенных денег.

## Известные открытые вопросы / не сделано

- BACKLOG.md п.5-7 не реализованы: генерализация под 4ч/1д, Above-маркеты
  как отдельный трек, единая политика капитала между потоками.
- `BLOCK_ORDERS_IF_PENDING` упоминается в `.env.example`/BACKLOG.md как
  "уже сделано", но физически не реализован в коде — это несостыковка,
  оставшаяся от исходного проекта до начала этой серии сессий, ещё не
  исправлена.
- `MIN_DISTANCE_ATR_RATIO` (порог ATR-гейта, по умолчанию 1.5x) не
  откалиброван на новой (корректной) шкале ATR — стоит пересчитать по
  накопленной статистике после того, как отработает какое-то время с
  Chainlink-фидом и новым масштабом свечей.
- Явного "гейта на расхождение источников" (напр. "если bybit и chainlink
  показывают разное направление — пропустить") не добавлено — решили, что
  переход на Chainlink как основной источник закрывает эту проблему по
  построению; расхождение фолбэк-провайдеров с реальностью видно постфактум
  через `priceSource` в логах, но не блокируется на лету.
- Фронтенд (`index.html`) собран без сборщика (JSX через babel-standalone в
  браузере) — при правках стоит прогонять через `@babel/standalone` в node
  для быстрой проверки синтаксиса перед выкаткой (без браузера).

## Конвенции при дальнейшей работе

- Пользователь просит присылать изменения **полным архивом**, повторяющим
  структуру проекта — не патчами/диффами.
- `.env.example` присылать также отдельным файлом (помимо архива) — иначе
  дотфайл иногда "теряется" на его стороне после распаковки.
- Перед сдачей: `npx tsc --noEmit -p tsconfig.json` (чисто) и
  `npx tsx scripts/verify-trading-logic.ts` (все тесты зелёные) —
  обязательный минимум перед каждой правкой.
- Пользователь давал реальные логи/скриншоты неудачных попыток как
  основной способ находить баги — стоит и дальше воспринимать такие разборы
  как приоритет №1 (реальные деньги/капитал), а не как второстепенную
  обратную связь.
